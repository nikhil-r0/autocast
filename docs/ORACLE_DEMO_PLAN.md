## 2. Exact Execution Runbook (Zero Faked Artifacts)

> **Note:** Do not run these commands until the pre-flight blockers in Section 4 (particularly Remotion Oracle prop wiring and `examples/ledgerly` dependency install) are resolved and committed cleanly on `main`.

### Step 0 — Environment & Key Setup (Run Once Before Filming)

1. Generate a runner Ed25519 keypair outside the repository (or under `.oracle-keys/`, which is gitignored via `.gitignore`):
   ```bash
   mkdir -p .oracle-keys
   openssl genpkey -algorithm ed25519 -out .oracle-keys/runner-private.pem
   openssl pkey -in .oracle-keys/runner-private.pem -pubout -out .oracle-keys/runner-public.pem
   ```
2. Build `ORACLE_TRUSTED_KEYS` JSON keyed by the SHA-256 of the SPKI DER public key (matching `computePublicKeyId` in `src/oracle/sign.ts`):
   ```bash
   node -e "
     const fs = require('fs');
     const crypto = require('crypto');
     const pubPem = fs.readFileSync('.oracle-keys/runner-public.pem', 'utf8');
     const pubKey = crypto.createPublicKey(pubPem);
     const keyId = crypto.createHash('sha256').update(pubKey.export({ type: 'spki', format: 'der' })).digest('hex');
     fs.writeFileSync('.oracle-keys/trusted-keys.json', JSON.stringify({ [keyId]: pubPem }, null, 2));
     console.log('Trusted key_id:', keyId);
   "
   ```
3. Install `examples/ledgerly` dependencies (required for isolated commit builds; ignored by `examples/ledgerly/.gitignore`), verify Kane CLI auth, and ensure a clean working tree:
   ```bash
   npm --prefix examples/ledgerly ci
   npm run build
   kane-cli --version
   git status --porcelain   # Must be empty before oracle runs
   ```
4. Export oracle environment variables for the session (never print `.oracle-keys/runner-private.pem` in recorded terminal views):
   ```bash
   export ORACLE_SIGNING_KEY=".oracle-keys/runner-private.pem"
   export ORACLE_TRUSTED_KEYS=".oracle-keys/trusted-keys.json"
   export ORACLE_RUNNER_ID="autocast-demo-runner-01"
   export GEMINI_API_KEY=""   # Optional: guarantees deterministic DEFAULT_NARRATIONS during --with-video
   ```
5. Compute and capture the canonical `spec_sha256` from the frozen spec:
   ```bash
   SPEC_PATH="examples/oracle/ledgerly-approval.json"
   SPEC_SHA256=$(node -e "import('./dist/oracle/spec.js').then(m => console.log(m.loadAcceptanceSpec('${SPEC_PATH}').specSha256))")
   EXPECTED_COMMIT=$(node -e "import('./dist/oracle/spec.js').then(m => console.log(m.loadAcceptanceSpec('${SPEC_PATH}').spec.target.expected_commit))")
   echo "SPEC_SHA256=${SPEC_SHA256}"
   echo "EXPECTED_COMMIT=${EXPECTED_COMMIT}"
   ```

### Step 1 — Run 1: Real Fail-Closed `hold` on Buggy Behavior (Exit `1`)

Run with `APP_BUG=approve-noop` and an isolated `RUN_ID=oracle-hold`, capturing verbatim terminal output for Beat 2:
```bash
mkdir -p out/oracle-drop
RUN_ID=oracle-hold APP_BUG=approve-noop \
  node bin/autocast.js --oracle "${SPEC_PATH}" \
  --expect-spec-sha256 "${SPEC_SHA256}" \
  2>&1 | tee out/oracle-drop/hold-terminal.log
HOLD_EXIT=${PIPESTATUS[0]}
echo "Hold exit code: ${HOLD_EXIT}"   # Must be 1
cp out/runs/oracle-hold/run-manifest.json out/oracle-drop/hold-manifest.json
```
*Expected sealed evidence:* `out/oracle-drop/hold-manifest.json` with `status: "failed"`, `oracle.verdict: "hold"`, `oracle.hold_reason: "kane_failed"`, `kane_verification.result_code: 740`, `closed_loop_repair.occurred: false`, and valid Ed25519 `signature`.

### Step 2 — Run 2: Real Signed `release` + 1080p Playwright Evidence (Exit `0`)

Run cleanly (no `APP_BUG`) with `--with-video` and `--publish stdout-json` under `RUN_ID=oracle-release`:
```bash
RUN_ID=oracle-release \
  node bin/autocast.js --oracle "${SPEC_PATH}" \
  --expect-spec-sha256 "${SPEC_SHA256}" \
  --with-video \
  --publish stdout-json \
  > out/oracle-drop/release-verdict.json \
  2> out/oracle-drop/release-terminal.log
RELEASE_EXIT=$?
echo "Release exit code: ${RELEASE_EXIT}"   # Must be 0
cp out/runs/oracle-release/run-manifest.json out/oracle-drop/release-manifest.json
```
*Expected sealed evidence:*
- `out/oracle-drop/release-manifest.json`: `status: "verified"`, `oracle.verdict: "release"`, `kane_verification.result_code: 100`, `application.state_verified: true`, `closed_loop_repair.occurred: false`, `artifacts.video` + `artifacts.poster` hashed, and valid Ed25519 `signature`.
- `public/source.mp4`: genuine 1080p Playwright replay generated by `replayAndRecord()` during this run.
- `out/oracle-drop/release-verdict.json`: exact `VerdictPayload` JSON (`spec_sha256`, `tested_commit`, `manifest_sha256`, `verdict: "release"`, `signature`).

*(Note: When `--publish stdout-json` is passed, `runOraclePipeline` routes human progress logs to `stderr` so `release-verdict.json` is pure JSON while `release-terminal.log` captures the exact execution trace.)*

### Step 3 — Run 3: Offline 8-Gate Verification (Exit `0`)

Verify the sealed release manifest completely offline (and capture the terminal output for Beat 4):
```bash
npm run verify:oracle -- out/oracle-drop/release-manifest.json \
  --spec "${SPEC_PATH}" \
  --commit "${EXPECTED_COMMIT}" \
  --trusted-keys .oracle-keys/trusted-keys.json \
  | tee out/oracle-drop/verify-oracle.log
```
*(Optional extra check for confidence: running `npm run verify:oracle -- out/oracle-drop/hold-manifest.json ...` exits `1`, proving payment gates reject the `hold` artifact.)*

### Step 4 — Bind Artifacts & Render Final `OracleDrop` Video

1. Assemble props from the real sealed manifests, real captured terminal logs, and `public/source.mp4` SHA-256 via a finalizer script (`scripts/finalize-oracle-drop.ts` — analogous to `scripts/finalize-showcase.ts`, validating via `verifyOracleManifest`):
   ```bash
   npx tsx scripts/finalize-oracle-drop.ts \
     --spec "${SPEC_PATH}" \
     --hold-manifest out/oracle-drop/hold-manifest.json \
     --release-manifest out/oracle-drop/release-manifest.json \
     --hold-log out/oracle-drop/hold-terminal.log \
     --release-log out/oracle-drop/release-terminal.log \
     --verify-log out/oracle-drop/verify-oracle.log \
     --verdict-json out/oracle-drop/release-verdict.json \
     --out out/oracle-drop/oracle-drop-props.json
   ```
2. Render the 78-second Part 2 feature drop video:
   ```bash
   npx remotion render OracleDrop out/oracle-feature-drop.mp4 \
     --codec=h264 \
     --concurrency=2 \
     --props=out/oracle-drop/oracle-drop-props.json
   ```
3. Extract frame-0 poster and inspect duration/codec/resolution (`1920x1080`, `30 fps`, `78.0s`):
   ```bash
   ffprobe -v error -show_entries format=duration,size:stream=width,height,r_frame_rate,codec_name -of json out/oracle-feature-drop.mp4
   ```

## 4. Pre-Flight Risks & Checks

1. **Same Commit (`APP_BUG=approve-noop`) vs. Two Distinct Git Commits (`expected_commit` pinning)**
   - `AcceptanceSpecSchema` (`src/oracle/spec.ts`) enforces a full 40-char hex SHA in `target.expected_commit`, and `spec_sha256` hashes the entire canonical spec including `expected_commit`.
   - **Recommended for filming:** Use `examples/oracle/ledgerly-approval.json` pinned to a single clean commit (where `APP_BUG=approve-noop` triggers Run 1's genuine Kane `740` `hold`, and clean env triggers Run 2's `release`). Both runs share the exact same `spec_sha256`, making the before/after comparison crystal clear (`--expect-spec-sha256` matches both).
   - **If contrasting two separate commits (`C_bug` vs. `C_fix`):** You must create two separate spec files (`ledgerly-buggy.json` with `expected_commit: C_bug`, `ledgerly-fixed.json` with `expected_commit: C_fix`), which produces two different `spec_sha256` digests, and ensure `runOraclePreflight` sees a clean git working tree (`git status --porcelain === ''`) before each run.
2. **`examples/oracle/ledgerly-approval.json` Currently Pins `eab4508...`**
   - Right now `examples/oracle/ledgerly-approval.json` points to commit `eab450840a7cec4d367defb9d4de96fcbcdcb96d`. That works on any clean checkout via `preparePinnedAppCheckout()` (`git archive` extraction), **provided `examples/ledgerly/node_modules` is installed first** (`npm --prefix examples/ledgerly ci`), because `LedgerlyLifecycleAdapter.start({ buildDistIfMissing: true })` symlinks `examples/ledgerly/node_modules` and runs `npm run build` inside the extracted checkout.
   - If you prefer `expected_commit` to match the final merged Oracle Mode `main` commit instead of `eab4508...`, update `examples/oracle/ledgerly-approval.json` in a follow-up commit after merging code changes, and commit cleanly before running `autocast --oracle`.
3. **Do Not Use `scripts/finalize-showcase.ts` for Oracle Drops**
   - `scripts/finalize-showcase.ts:30` calls `verifyRunManifest(..., { requireVerifiedStatus: true, requireArtifacts: true })`, which rejects Oracle manifests (no `visual_qa`, `mode: 'oracle'`). Likewise `scripts/verify-provenance.ts:28-33` rejects `mode: 'oracle'`. Use `npm run verify:oracle` and a dedicated `scripts/finalize-oracle-drop.ts` backed by `verifyOracleManifest()`.
4. **`out/run-manifest.json` Overwrite Between Run 1 and Run 2**
   - Every `autocast --oracle` run overwrites `out/run-manifest.json` (`src/oracle/runner.ts:328`), while also writing `out/runs/<runId>/run-manifest.json`. Always set distinct `RUN_ID=oracle-hold` and `RUN_ID=oracle-release` and copy each run's manifest into `out/oracle-drop/` immediately.
5. **Port `8080` Conflicts & Deterministic Seed Reset**
   - Ensure no manual `npm run app` or stray server is occupying port `8080` before filming; `LedgerlyLifecycleAdapter.start({ strictPort: true })` fails with exit `2` if an unrelated process holds `8080`.
   - Between Kane verification and `replayAndRecord` (`src/capture/replay.ts:74`), `replayAndRecord` posts to `/api/reset` without a body, which `examples/ledgerly/server/index.js:58` defaults to `'ledgerly-default-v1'`—compatible with `examples/oracle/ledgerly-approval.json`.
6. **Gemini Narration Fallback During `--with-video`**
   - Although Oracle Mode never uses Gemini for `spec.objective`, `defaultCaptureOptionalVideo()` (`src/oracle/runner.ts:216`) calls `generateNarration()`, which calls Gemini if `GEMINI_API_KEY` is set. Set `GEMINI_API_KEY=""` for deterministic `DEFAULT_NARRATIONS` captions (or review `storyboard.json` captions before final `OracleDrop` render).
7. **Keep Private Signing Keys Off-Screen**
   - Store keys under gitignored `.oracle-keys/` and pass a file path (`ORACLE_SIGNING_KEY=.oracle-keys/runner-private.pem`) rather than pasting PEM text in terminal commands so neither recorded terminal frames nor OCR scans can capture key material.
